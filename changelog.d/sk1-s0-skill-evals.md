### ADDED — apeGmsh skill eval harness and deterministic graders (SK1-S0, #2003)

`scripts/skill_eval.py` measures the `apegmsh` user skill locally. It installs the canonical `skills/apegmsh/` tree at a git ref (its hash is `git rev-parse <ref>:skills/apegmsh`) into an isolated `claude -p` config, runs six scripted tasks in a skill, a no-skill and a previous-record arm, runs a 20-prompt trigger set, and appends one JSON line per run to `evals/apegmsh/runs/`. `--dry-run` prints the plan and the skill hash without calling `claude`. The maintainer runs it; CI never does.

`evals/apegmsh/graders.py` grades a script by re-running it alone, linting it with `lint_model_script.py`, and checking an oracle that names the right answer: FEMData invariants (exact areas and volumes, nodes on their edges, grading, conformity) for the two mesh tasks and the multi-part assembly; method-of-sections statics and an independent numpy stiffness solve for the truss; Rayleigh's period and a golden for the frame; equilibrium, the Flamant slope and the plastic share for the staged footing read-back. A solve or read-back grade also needs run evidence from a grading probe: an apeSees bridge built from a FEMData, OpenSees solving a model of that size, and, for the read-back, numbers that reproduce the recorder files, so numbers computed without apeGmsh and OpenSees fail. `tests/test_skill_eval_graders.py` holds every grader to its known-good scripts (the skill's reference scripts) and its frozen known-bad ones (the `SKILL.md` skeleton without `Base`, the `distance(edges=)` field fence, and one wrong model per task); the mesh tasks run in the suite lane and the solves in live-stock.
