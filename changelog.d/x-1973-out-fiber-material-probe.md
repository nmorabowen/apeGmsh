### ADDED — a live probe: plain `.out` element recorders carry fibre and per-material responses (program slice #1973, #1961 Q4)

`tests/opensees/live/test_out_fiber_material_probe_live.py` records, with raw `ops.recorder("Element", ..., "-precision", 16)`, `section 1 fiberData` and `section 1 fiberData2` on 2-D and 3-D `dispBeamColumn` and `forceBeamColumn` cantilevers with elastic fibre sections, and `material <gp> stress|strain|damage` on a `stdBrick`. Each value is checked against an analytic oracle: fibre strain = ε₀ − κz·y + κy·z with stress = E·strain; a prescribed trilinear displacement field that gives each of the 8 Gauss points its own stress and strain, so a wrong Gauss-point index fails; and the cracked damage of an `ASDConcrete3D` with `-Td 0 0 0.9` pulled to 4·εt, d+ = 0.1(ε/εt − 1). The tolerance is rtol 1e-12, except damage, which is held to 1e-6 because the material's pre-crack secant is 0.999991·E (measured error 9e-8). Each value is also compared with `eleResponse` as a secondary check. The probe runs on the `live-stock` lane (pip openseespy), where it settles whether pip users need an in-process fibre or material reader once `DomainCapture` goes (#1767). The engine carries these responses, but apeGmsh's own `.out` emit and parse do not request them yet, which a follow-up owes. Tests only; no reader or recorder code changes.
