### CHANGED — `land_pr.py` check 10 lands up to three file-disjoint PRs per green `main` run (#2919)

Check 10 used to refuse every landing while `main`'s Tests run on its head H was in progress, unless the PR's checks had run on a base containing H, so a program day landed one PR per run of about 45 minutes. Under the owner's ruling of 2026-11-12 it now also admits a PR as one of at most three landings on the last green commit G: at most two commits sit in G..H, none of them has a required job that has already failed, and the PR's changed files (both names of a rename) are disjoint from G..H's, read from `compare/G...H` by SHA at landing time and checked against `main`'s commit order. A refusal names G, the group size and the disjointness result; a G..H that cannot be read, or that disagrees with the commit order, refuses. Before a merge the group rule admitted, the script re-reads `main`'s head and refuses if it moved. `fixes-red-main` is still the only override. The #1858 and #1866 replays stay refused: 3af31061's lock-tests had already failed when each landed.
