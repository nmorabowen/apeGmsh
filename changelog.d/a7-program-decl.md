### CHANGED — `/opensees/program` records each call's declaration (opensees 2.31.0); `model_hash` changes once (A7, #1839)

`apeSees.h5` now fills the `decl` column of `/opensees/program`, which held `-1` on every run since 2.23.0. Each emitted call carries the `/opensees/decls` row of the declaration that made it when the emit proves it: a material, section, transform, element, time series, pattern, damping or region by its tag, and a fix, mass, recorder, stage removal or flip, HOLD, Rayleigh or `/opensees/commands` row by the declaration the bridge opened on it. Every other call keeps an explicit `-1`: nodes, the neutral-declared MP constraints and reinforce ties, the parts of a record (loads, fibers), the analysis chain and stage brackets, the side-channel stores' calls, and any call whose declaration is not known when it is emitted. A stage's calls therefore join to their declarations through the program alone. `H5Model.program()` refuses a `decl` outside `-1` and the declaration rows. A new hash-excluded marker, `/opensees/decls@program_decl`, is `"complete"` on an emit and `"absent"` on a `to_h5` rewrite of an older file, whose column was never recorded. `h5_reader.records_program_decl(table)` reads it, and the new join query `H5Model.program_declarations()` raises `ProgramDeclAbsentError` on such a file instead of reporting its calls as undeclared. The column is hashed, so every archive the bridge writes gets a new `model_hash` once, at this version. A file written earlier keeps its stored hash until it is re-emitted, and `OpenSeesModel.to_h5` echoes the source's column unchanged. A results file written against the old hash then reports a lineage mismatch (`Results.lineage` warnings; the viewer will not draw it) until the analysis is re-run. A 2.30.x reader refuses a 2.31.x file.
