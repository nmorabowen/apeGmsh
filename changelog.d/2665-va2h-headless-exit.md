### FIXED — apeGmshViewer's headless modes exit non-zero on a crash, a hang or a throw, never wait forever (VA2h, #2665)

`--render`, `--describe`, capture, measure and measure-results used to hang on a throw inside startup (Electron's modal), on a crashed renderer, or on a renderer that stopped answering, and a capture whose own sequence threw exited 0 (`app.quit()` ignores `process.exitCode`). Each now exits 1 with the reason on stderr. A renderer that leaves main's one-second question unanswered for `--hang-ms` (default 60000) counts as hung, since Electron's `unresponsive` never fires for a hidden window. A render that cannot finish removes the stills it wrote, whose entries were the renderer's, and writes a `manifest.json` that refuses the run (key `render`) and names the shot it stopped on (INV-6). A capture writes the reason to `<out>.error.txt`. A still whose write throws part way is removed, so no partial PNG stands beside its refusal. `test/spec/headless-exit.e2e.ts` forces each fault in each mode.
