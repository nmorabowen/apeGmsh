### FIXED — apeGmshViewer's headless modes exit non-zero on a crash, a hang or a throw, never wait forever (VA2h, #2665)

`--render`, `--describe`, capture, measure and measure-results used to hang on a throw inside startup (Electron's modal), on a crashed renderer, or on a renderer that stopped answering, and three failures exited 0: a capture whose own sequence threw, a capture whose `capturePage` returned an empty image, and a measure whose `.ladruno` read row failed (`app.quit()` ignores `process.exitCode`). Each now exits 1 with the reason on stderr. A renderer that leaves one of main's once-a-second questions unanswered for `--hang-ms` (default 60000), timed from when it was sent, counts as hung, since Electron's `unresponsive` never fires for a hidden window; a tick that fires late because main itself was busy gives no verdict, so main's own stall is not reported as a hung renderer. A render that cannot finish removes the stills it wrote, whose entries were the renderer's, and writes a `manifest.json` that refuses the run (key `render`) and names the shot it stopped on, the one whose capture was in flight included (INV-6). A capture writes the reason to `<out>.error.txt`. A still whose write throws part way is removed, so no partial PNG stands beside its refusal. `test/spec/headless-exit.e2e.ts` forces each fault in each mode.
