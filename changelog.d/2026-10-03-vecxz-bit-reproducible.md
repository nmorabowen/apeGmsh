### FIXED — orientation-derived `geomTransf` vecxz is bit-identical on every host

The per-element `vecxz` that an `orientation=` transform fans out to (`Cartesian`, `Cylindrical`, `Spherical`, `AlongBeam`) could differ in its last bit between hosts, and between element-tag modes on the same CI runner: `np.dot` and `np.linalg.norm` round according to CPU dispatch, the BLAS build and memory alignment, and the first-seen dedupe wrote whichever bits it got (#1279). The orientation rule and the element tangent now run on Python floats in a fixed operation order, so each step is one correctly rounded IEEE-754 operation. The golden arch's third transform now emits `0.2588190451025208 0.0 0.9659258262890682` (previously `0.25881904510252085 0.0 0.9659258262890684`); a non-zero `roll_deg` still goes through libm `sin`/`cos`. `tests/opensees/unit/test_vecxz_determinism.py` pins the bits and keeps numpy reductions off the path, and `test_fem_mode_changes_only_element_tags` compares decimal values exactly again. The golden regen tool gains `--exact`, which rewrites decks that differ only within the float tolerance.
