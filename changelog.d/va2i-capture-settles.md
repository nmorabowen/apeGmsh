### FIXED — apeGmshViewer's app-chrome `--render` stills no longer report `ok` with a stale frame (VA2i, #2696)

A hidden window's `capturePage` copies the last frame the window showed, which can predate the page's latest changes. Because of this, an app-chrome still could report `ok` with no panels, or with the phase readout a step old. Main now captures the page until two consecutive captures are pixel-identical, at most `--capture-tries` times (default 10; a value below 2 is refused, exit 2). A page that never settles refuses the shot, names it, and writes no PNG. Two matching captures prove that the frame stopped changing, not that it is the latest frame. `test/spec/render.e2e.ts` forces a stale first capture and a page that never settles. It compares the ghost stills over the whole image, with the readout mask removed. It checks INV-1 against each run's own `--user-data-dir` instead of `%APPDATA%`, which other viewer windows on the machine write to.
