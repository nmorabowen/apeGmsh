### CHANGED — `FORK_PIN` moves to ladruno-v20261023 (fork `bdb69cea5`); the #2444 activation refusal stays on every fork target (#2514)

The nightly `live-fork` lane now tests fork build `bdb69cea5`, the merge of
nmorabowen/OpenSees#1005. That build no longer resets the class-wide
`ManzariDafalias` stage flag when a later stage constructs new materials, so
the s1-flip / s2-activation run keeps its plastic answer on it.

The stage-close refusal of that pattern (`FORK_RESETS_STAGE_STATIC`) is
unchanged and fails closed on every fork target. Older fork builds, such as
79e062367, still reset. The check runs at stage close, before any engine is
bound, so it cannot know the build a deck will run on. In-process,
`ladrunoBuild()` returns the exact sha, but a bare sha cannot prove that the
build descends from fork commit `43b235bbb`. The refusal message now says
so. It can be lifted once the fork registers a capability marker for the
fix (#2444), or once the live route checks the bound build against an
allowlist (#2516).

The live reset tests now expect the reset only on a fork build that lacks
the fix, read from a table of measured builds. A unit lock fails when
`FORK_PIN` names a build that is not in that table. The `ladrunoSchema`
build floor of the `materialState` deck guard is unchanged: the new pin
descends from `100eb9ae` and registers the command.
