# API gaps found by the readability workshop

Library gaps that scripts had to work around. They are not style rules: the fix is in
apeGmsh, not in the contract. Each entry names the loop, the scripts and the evidence
(tangle line, or `friction` for writer-reported API friction).

## Results read-back after a live run

- **No in-process read-back by label after `ops.analyze`.** Node displacement and element force need raw openseespy (`nodeDisp`, `eleResponse`, `getEleTags`) or a capture/recorder route. Loop 1: a (tangle l.109, three `# raw-ops:` lines), b (tangle l.86), c (friction), d (friction). Loop 2: every frame script read `nodeDisp` raw after `ops.analyze`, and reactions also need a raw `reactions()` call before `nodeReaction`: a (tangle l.302, invented `ops.raw`), b (tangles l.199, l.201), d (tangle l.186), e (tangles l.178-198), f (tangle l.117); c did not find the raw route and reported drifts of 0.0 (tangle l.220). `ops.analyze` returns only a status int. Loop 3: a staged model cannot run live at all (`ops.analyze` / `ops.eigen` are refused once stages exist), so every staged script read a text Node recorder back by hand: b (tangle l.200, manual `split` loop), c (tangle l.110, `reshape` guessing the column count), e, f (friction).
- **Live OpenSees element tags differ from FEMData element ids, and no group/label -> live-tag map exists.** Scripts re-derived member kind from coordinates or matched by `frozenset(eleNodes)`. Loop 1: a (friction, l.121), b (tangle l.89; node tags did match), d (tangle l.161). Loop 2: live node tags equal FEM node ids, but no doc says so; b found it only in the live emitter source (friction).
- **A one-node group still returns a set.** `ops.nodes.get(pg=)` gives a NodeSet and `fem.nodes.select(pg=)` an id array even for one node, so scripts write `.tags[0]`, `.ids[0]` or `[node] = ...`; `ops.nodes.get` has no `label=` selector, so each read-back joint needs its own physical group. Loop 2: b (l.199), d (l.181, friction), e (l.187, friction), f (l.117).
- **`EigenResult` fields are undocumented.** `.periods` exists but is not in the skill or the lookup index; f recomputed periods from `.eigenvalues` by hand (tangle l.101), b and d confirmed `.periods` by reading source or guessing. Loop 2: b, d, f (friction).
- **Capture ceremony for one static step.** `DomainCaptureSpec` lives at the deep path `apeGmsh.results.capture.spec`; one step needs `begin_stage` / `analyze` / `step(t=)` / `end_stage` (about 8-10 lines). Loop 1: c (tangles l.20, l.124-127).
- **Scalar extraction needs `.values[-1, 0]`.** Loop 1: c (tangle l.144, repeated l.158-159).
- **Two files to rebuild Results** (`ops.h5` model + capture run). Loop 1: c (tangle l.120).
- **MPCO reader does not surface Truss `force`;** `available_components()` is empty, so d fell back to per-group text Element recorders with column order assumed equal to group element-id order and a hand-built id -> label map. Loop 1: d (tangles l.159-161, friction).
- **No verb closes the live domain / flushes recorders,** so the `.mpco` stays open for write and d ran the deck in a subprocess (`ops.py(run=True)`). Loop 1: d (tangle l.139, friction).
- **`Results.from_mpco(..., model_h5=)` loses physical groups** unless `fem=` is passed; not documented. Loop 1: d (friction).
- **Element recorder has no time column by default,** and the docstring does not say so. Loop 1: d (friction).
- **`GaussSlab.element_index` vs `NodeSlab.node_ids`** naming is inconsistent. Loop 1: c (friction).
- **`fem.elements.labels.get_name(tag)` is not element-id -> label, and `connectivity("bottom_1")` fails on a curve label** although `element_ids` works. Loop 1: d (friction).

## Meshing 1-D members

- **No one-element-per-member switch for trusses and frames.** `set_global_size` still splits bars, leaving collinear interior nodes (singular stiffness); every working script looped `set_transfinite_curve(label, n_nodes=2)`, and two scripts fell into the trap. Loop 1: e (tangle l.81, 45 nodes / 56 elements), f (tangle l.37, 279 / 296), a, b, c, d (friction). Loop 2 (frames): `set_global_size(6.0)` still gave about three elements per 6 m member, because gmsh reads the size at the points; b needed `set_size_all_points` plus a comment (tangle l.145), f put `mesh_size=` on every point, d got 119 nodes, e accepted two elements per beam, and a and c split members (and spread loads onto mid-span nodes) with small sizes. Loop 2: a, b, c, d, e, f.
- **Gmsh `Info :` lines print despite `verbose=False` and `APEGMSH_QUIET=1`.** Loop 1: a, b, c, d (friction).

## Bridge surface and naming

- **Elastic uniaxial is `ElasticMaterial`, not `Elastic`;** the AttributeError hint suggests `ElasticPP`. One writer faked elasticity with `Steel02(fy=1e9)`. Loop 1: a, b, c, f (friction).
- **The non-staged analysis chain is undocumented;** `analyze()` raises BridgeError until constraints, numberer, system, test, algorithm, integrator and analysis are all registered. Loop 1: a, b, f (friction). Loop 2: d, f (friction: seven flat calls, no non-staged example); d also had to add `constraints.Transformation()` by hand although the skill says the handler is auto-selected.
- **`algorithm.Linear` still requires a convergence test** whose tolerance has no effect. Loop 1: c (friction). Loop 2: e (tangle l.178, `max_iter=1` kept as ceremony).
- **OpenSeesAutoEmitWarning on `ops.h5()` / `ops.eigen()` when the constraints handler is declared later,** so the analysis chain must move ahead of the model archive and the modal run instead of sitting with the static analysis it belongs to. Loop 2: b, e (friction).
- **A detached rigid-diaphragm master leaves uz, rx, ry free and unconnected.** Nothing fixes or warns about them, so the stiffness is singular and the default eigen solver returns garbage (`aii < 0`, ~1e-7 eigenvalues); scripts fix them by hand. Loop 2: d (tangle l.148, friction), f (tangle l.83, friction).
- **`rigid_diaphragm` rough edges:** it refuses a `decouple_node` master, so the master must be a labelled point in a point group kept with `get_fem_data(dim=None)` (d, f friction); it needs `master_point=` even when the master label resolves to one node (b friction); `plane_tolerance` defaults to 1.0 model unit, which is dangerous in metres with short storeys (e friction). Loop 2.
- **`ops.fix` / `ops.mass` take `pg=` or `nodes=` but not `label=`,** so every point label is promoted to a dim-0 physical group just to be addressable. Loop 2: b (friction), e (friction, same for `ops.nodes.get`). Loop 3: `ops.recorder.Node` also takes no `label=`, so the footing-centre point was promoted to a dim-0 group to be recorded (f friction), or recorded by a raw node id taken from `fem.nodes` on the assumption that the bridge uses the same ids (c friction).
- **`geomTransf` orientation is all by hand.** Each member direction needs its own transform with a hand-derived `vecxz`, the reader must do the cross product to see which inertia is strong, nothing checks Iy/Iz against the orientation, an aligned vector fails with "parallel to x axis", and omitting `vecxz` silently takes a default. Loop 2: a (friction), b (tangle l.156), c (tangle l.151).
- **`physical.add_curve` / `add_point` are typed `tags: list[Tag]` but accept label lists;** the skill shows only single-label calls. Loop 2: d, e (friction).
- **`ndm=2` on a 3-D geometry** fails late (zero-length vertical members) rather than with a clear dimension error. Loop 2: a (friction; the script never ran).
- **Giving several entities the same `label=` warns "Merging" on every call,** which pushes scripts to per-bar labels plus `physical.from_labels`. Loop 1: c, d (friction).
- **Point physical-group fan-in** (same `name=` from several labels) works but is undocumented. Loop 1: a (friction).

## Skill and lookup drift

- **Lookup CLI** (`python -m apeGmsh.studio.lookup`) misses, or prints nothing, for `ops.element.Truss`, `pattern.Plain`, `analysis.Static`, `fem.elements.select`, `results.elements.get`, `DomainCaptureSpec`, `ops.wipe` and others, and takes 15-25 s per symbol. Loop 1: a, c, d (friction). Loop 2: misses `fem.nodes.select`, `ops.nodes`, `EigenResult`, `NodeSet`, and class-qualified names such as `apeSees.eigen` and `ConstraintsComposite.rigid_diaphragm` (b, e friction). Loop 3: misses `ops.element.quad`, `ops.element.SSPquad`, every `apeSees.nDMaterial.*` and `apeSees.element.*` (c had to introspect namespaces), `nDMaterial.DruckerPrager` and its nine-parameter signature (f), `g.model.geometry.add_polygon`, `Algorithm2D`, and the stage-builder verbs `s.pattern`, `s.run`, `s.analysis` (b, e); it crashes with UnicodeEncodeError on cp1252 consoles when a docstring has a Greek letter (`g.loads.gravity`) unless PYTHONIOENCODING=utf-8 (e) (friction).
- **Skill drift:** `physical.from_labels` signature (c); `in_box` argument form (b); `fem.elements.get` removed (b); `domain_capture` docstring uses positional `analyze(1, 1.0)` (c); no truss recipe (b); `from_mpco` needs `fem=` for pg queries (d). Loop 1 (friction). Loop 2: the cheatsheet's `rigid_diaphragm(master_label, slave_label, *, perp_dirn=3)` is out of date (d); the `rigid_diaphragm` docstring example seems to swap master and slave (e); no frame recipe saying how to get one element per member (b); `EigenResult` and the NodeSet API are absent (d, e) (friction). Loop 3: the cheatsheet shows `g.mesh.structured.set_recombine(dim, tag)` but the signature is `set_recombine(tag, *, dim=2)` (f); `g.mesh.generation.set_algorithm` needs `(tag/dim, algo)` (c); recombination is not under `g.mesh.generation`, and calling it after `generate` silently gave tri3 on the first try (c); the skill never says that `get_fem_data(dim=2)` keeps dim-1 and dim-0 groups (e); nor that `g.loads.line(magnitude=)` is a force per length, not a pressure (f). Control a also reported `add_rectangle(x, y, z, dx, dy)` read as corners, `PhysicalGroups.add_line` (it is `add_curve`), a missing `set_size_at_point`, and `LoadControl(dlam=)` keyword guessing (friction).

## Staged analysis (loop 3: 2-D strip footing, two stages)

- **`ops.fix` refuses a second fix on the same node and DOF,** even when both declarations are the same homogeneous fix, so the textbook "base fixed, sides on rollers" setup fails at the two base corners ("Duplicate fix / mass targets ... global pool AND global pool"). Scripts dropped from group names to node-id lists (`fem.nodes.select(pg=sides) - base_nodes`, then `ops.fix(nodes=ids)`) or a coordinate mask; only `g.constraints.bc(...)` plus `ops.fix_from_model()` merges them, and the `ops.fix` docs do not say so. Loop 3: b (tangle l.151, friction), c (tangle l.73, friction), e (tangle l.184, friction), f (friction); control a gave up the side rollers (tangle l.51).
- **`g.constraints.bc(dofs=)` takes a 3-entry mask in a 2-D, ndf=2 model** (`dofs=[1, 1, 0]`). Loop 3: f (tangle l.104).
- **The stage step is stated twice:** `LoadControl(dlam=step)` inside `s.analysis(...)` and `s.run(dt=step)` carry the same number, nothing says which one the recorded time follows, and they drift (c used `dt=1.0` with `dlam=1/N`). Loop 3: b (tangle l.181), c (tangle l.97), f (tangle l.157).
- **No stage-level shared analysis chain.** The integrator must sit inside `s.analysis(...)` with a per-stage `dlam`, so scripts build a `dict` of six primitives and splat it into each stage (`**solver`), or wrap it in a helper. Loop 3: b (tangle l.165), e (friction), c (tangle l.80).
- **Stage-boundary semantics are undocumented.** Each stage ends with `loadConst -time 0` and `wipeAnalysis`, so pseudo-time and the load factor restart at 0; a `Path` series spanning both stages silently applies zero footing load in stage 2 (flat curve, no error). Found only by reading the emitted deck. Loop 3: b, e, f (friction).
- **`ops.py(path, run=True)` returns `None`** although it is typed `RunSolverStats | None`, so there is no status to assert; scripts assert on the recorder row count, which works only because the deck exits on a failed increment. Loop 3: b, e (friction).
- **`ops.py(run=True)` picks the interpreter as `$OPENSEES_VENV` -> `which('python')` -> `sys.executable`;** where `which('python')` is a Python without openseespy the run fails, so `python=sys.executable` and `import sys` appear in a model script. Loop 3: e (tangle l.220, friction).
- **`ops.recorder.Node(time_format=)` accepts only `'step'` or `'dt'`,** and `'dt'` is the one that writes the `-time` column; only the error message lists the values. Loop 3: b, e (friction).
- **Collapse surfaces only as "analyze FAILED at increment N",** with no hint that the soil reached its limit load. Loop 3: f (friction; cohesion was raised to 18 kPa to reach 300 kPa).
- **WarnBodyForceDoubleCount fires falsely** when an element `body_force=` region shares nodes with any `from_model` case, even a non-gravity line load; its advice (element body force cannot be ramped, use a `g.loads.gravity` case) was right. Loop 3: b, c (friction).

## Geometry, groups and emitted deck (loop 3)

- **A second `g.labels.promote_to_physical(..., pg_name=X)` into an existing group silently replaces it.** The "Footing" group kept one half, its nodes carried 300 kN/m instead of 600, settlement came out halved, and nothing warned. It should merge or raise. Loop 3: b (friction; found by summing the deck's load lines).
- **No block-grid or graded transfinite helper.** A structured quad mesh graded away from the footing needs a hand-built grid of points, lines and surfaces and a `set_transfinite_curve` per line (about 40 lines of loops). Loop 3: e (tangle l.158, friction).
- **No verb names "the node at this point" without splitting the geometry;** the footing edge had to be split at its centre to make a nameable node. Loop 3: e (friction); b and f did the same.
- **`in_box` on curves selects only entities wholly inside the box,** so a slightly shrunk box selected nothing and the group was never created, with no warning. Loop 3: c (friction).
- **numpy scalars passed to bridge primitives are emitted as `np.float64(...)`,** and the deck fails with `NameError: name 'np' is not defined`. Loop 3: c, f (friction; cast with `float()` or used `math`).
- **`DruckerPrager(rho=)` is the friction parameter while `density=` is the mass density,** an OpenSees naming clash carried into the typed API. Loop 3: f (tangle l.124).
